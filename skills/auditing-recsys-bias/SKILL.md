# Auditing Recommender Bias

## Overview

Clicks only happen on items the old system showed. A model trained and evaluated on those clicks is rewarded for **imitating the logging policy**, and every retrain on its own feedback narrows exposure further. **Core principle:** offline NDCG on logged clicks is not evidence that a model is better for users. Before go-live, measure exposure concentration against the current model and a popularity baseline, check where the NDCG gain comes from, and set up the data (impression log, exploration traffic, holdout) that can actually answer "better?".

## Audit (before go-live, same users, same cutoff)

1. **Popularity baselines** on the same split (all-time and last N days). If the new model's gain over the old one is matched by popularity, the gain is popularity (REQUIRED SUB-SKILL: evaluating-recommenders-offline).
2. **NDCG/hit rate by item popularity bucket** (head 1%, mid, tail 80%, cold). A gain only in the head bucket is concentration, not personalization.
3. **Exposure metrics, old vs new:** catalog coverage of top-k, Gini of position-weighted exposure, share of slots taken by the top 1% of items, exposure share of item groups that matter (new items, small providers, categories).
4. **Feedback-loop exposure:** what fraction of training clicks came from recommendation slots vs search/browse? Without impressions, no debiasing estimator (IPS/SNIPS) is possible — say so instead of computing a "debiased" number.
5. **Go/no-go rule written before seeing the result:** e.g., ship to an A/B test only if coverage and Gini are not worse than the current model by more than an agreed margin and the gain is not confined to head items. Online decision = A/B with a persistent holdout (REQUIRED SUB-SKILL: designing-ab-tests).
6. **Data to fix the loop, from day one:** log impressions with position and propensity; reserve a small exploration bucket (random or randomized-slot traffic, 1–5%) — the only unbiased test set you will ever have.
7. **People-facing groups** (users by region/age, providers): REQUIRED SUB-SKILL: auditing-fairness.

"NDCG went up, the director approved, deploy is scheduled" is the scenario this audit exists for. The audit is an hour of work on data you already have; it does not need to block an A/B test — it decides whether the release goes to 100% or to an A/B.

## What Logged NDCG Rewards

Simulation: 4,000 users, 2,000 items with known true click probabilities; 12 weeks of an ALS retrained weekly on its own clicks (started from a popularity policy). Evaluated on the next week's logged clicks vs on a random-exposure bucket:

| Model | NDCG@10, logged clicks | NDCG@10, random bucket | True clicks per 10-item list | Coverage | Gini | Top-1% share of slots |
|---|---|---|---|---|---|---|
| Popularity | 0.019 | 0.008 | 2.3 | 0.5% | 0.995 | 100% |
| ALS on its own feedback | **0.043** (best) | 0.013 | 3.5 | 12.6% | 0.963 | 37% |
| True preferences (oracle) | 0.024 | **0.036** (best) | **9.2** | 56.8% | 0.834 | 19% |

- On logged clicks the feedback-loop ALS beat the **perfect** model by 80%; on unbiased data the perfect model was 2.9× better and produced 2.6× more true clicks.
- An IPS estimate from the random bucket (clicks on recommended items / exposure probability) tracked the truth: 2.26, 3.31, 9.58 vs 2.32, 3.52, 9.21 — this is what an exploration bucket buys.

## Implementation

```python
import logging

import numpy as np
import pandas as pd

logger = logging.getLogger(__name__)


def compute_exposure_metrics(
    recs: pd.DataFrame, n_catalog: int, item_group: pd.Series | None = None
) -> dict[str, float]:
    """Concentração da exposição nas listas top-k servidas ou simuladas.

    Parameters
    ----------
    recs : pd.DataFrame
        Uma linha por slot recomendado: ``user_id``, ``item_id``, ``rank`` (1 = topo).
    n_catalog : int
        Número de itens recomendáveis no catálogo (itens nunca exibidos contam).
    item_group : pd.Series, optional
        Grupo de cada item (índice = ``item_id``), ex.: "novo"/"antigo", fornecedor.

    Returns
    -------
    dict[str, float]
        ``coverage``, ``gini`` da exposição (ponderada por 1/log2(rank+1)),
        ``head_1pct_share`` e a fatia de exposição por grupo.

    Examples
    --------
    >>> compute_exposure_metrics(recs_new, n_catalog=40_000, item_group=is_new_item)
    """
    weight = 1.0 / np.log2(recs["rank"].to_numpy() + 1)
    exposure = pd.Series(weight, index=recs["item_id"].to_numpy()).groupby(level=0).sum()
    values = np.zeros(n_catalog)
    values[: len(exposure)] = np.sort(exposure.to_numpy())[::-1]
    cum = np.cumsum(np.sort(values))
    gini = 1 - 2 * cum.sum() / (cum[-1] * n_catalog) + 1 / n_catalog
    n_head = max(1, n_catalog // 100)
    result = {
        "coverage": len(exposure) / n_catalog,
        "gini": float(gini),
        "head_1pct_share": float(values[:n_head].sum() / values.sum()),
    }
    if item_group is not None:
        shares = exposure.groupby(item_group.reindex(exposure.index)).sum() / exposure.sum()
        result |= {f"exposure_share_{g}": float(s) for g, s in shares.items()}
    logger.info(f"Exposição: cobertura={result['coverage']:.1%} gini={gini:.3f} top1%={result['head_1pct_share']:.1%}")
    return result


def compute_hit_rate_by_popularity(
    recs: pd.DataFrame, test: pd.DataFrame, train_counts: pd.Series, k: int = 10
) -> pd.DataFrame:
    """Fração das interações de teste acertadas no top-k, por balde de popularidade do item.

    ``train_counts``: interações de treino por item (índice = ``item_id``).
    Ganho só em ``head_1pct`` = concentração, não personalização.
    """
    ranks = train_counts.rank(ascending=False, method="first")
    n = len(train_counts)
    bucket = pd.cut(ranks, [0, 0.01 * n, 0.2 * n, n], labels=["head_1pct", "mid", "tail_80pct"])
    top = recs.loc[recs["rank"] <= k, ["user_id", "item_id"]].assign(hit=1)
    hits = test.merge(top, how="left", on=["user_id", "item_id"])
    hits["bucket"] = hits["item_id"].map(bucket).cat.add_categories("cold").fillna("cold")
    return hits.groupby("bucket", observed=False).agg(n_test=("hit", "size"), hit_rate=("hit", lambda h: h.notna().mean()))
```

Verified with pandas 3.1.0, numpy 2.5.4; simulation with implicit 0.7.3 ALS. Run both functions on the old and new model's top-k for the **same users**, side by side. To get top-k from implicit: `ids, _ = als.recommend(user_idx, X_train[user_idx], N=10, filter_already_liked_items=True)`.

## Common Mistakes

| Mistake | Fix |
|---|---|
| "1% of items in every list is normal, they are the popular ones" | Measure it against the current model and the popularity baseline; it is the number the loop makes worse |
| Weekly NDCG on clicks from the model's own lists as the monitoring KPI | It rises as the model narrows. Monitor coverage, Gini, head share and the holdout comparison next to it |
| "Debiasing" with IPS without an impression log | Not possible; log impressions and propensities first |
| Diversity re-ranking added to fix the metric | Decide on it after the audit, via A/B; re-ranking without measurement trades NDCG for an unknown effect |

## Rationalizations

| Excuse | Reality |
|---|---|
| "No audit needed, we measured what matters" | Logged NDCG ranked the perfect model below the feedback-loop model |
| "The director approved, deploy is today" | The approval was for an NDCG gain; the audit says what that gain is made of. Present it; the release can still go out as an A/B with holdout |
| "Ship now, add monitoring later" | Without impressions and a holdout logged from the first day, "later" has nothing to compare against |
| "Popular items are what users want" | Only for the items they were shown; 0.5% of the catalog was shown under popularity |

## Red Flags — Stop

- Top-1% items take >30% of slots or coverage drops vs the current model
- NDCG gain concentrated in the head bucket; flat or negative in tail/cold
- Training data = clicks on the previous model's recommendations, no impressions
- The release plan has no holdout group
